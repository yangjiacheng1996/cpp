# 项目背景
我想系统性学习C和C++语言的语法。并且日后打算手动编程，能看得懂大模型写出来的代码。
我不是学生而是上班族，日常学习时间是碎片化的，不能像大学生那样连续多个小时高强度连续学习。
而世面上的绝大部分C/C++书籍都是面向学生的，缺少卡片式学习方式，将知识拆解成一张张小卡片，每个卡片在5分钟内学完。
我之前做运维工作的时候，看过很多“5分钟玩转”系列书籍，比如《每天5分钟玩转Docker》、《每天5分钟玩转Kubernetes》、《每天5分钟玩转Openstack》等等。
我想这个方式可以用于学习C和C++。

# 项目约束
1. 卡片篇幅。我在项目根目录创建了两个目录，分别是C/和CPP/，用于存放C语言和C++语言的语法糖小卡片。每个小卡片是一个markdown文件，字数控制在3000 Token以内，不算标点和符号，否则5分钟内看不完。
每个小卡片3000 Token的好处是：1. 内容切分，让作者有边界感，不要让多个知识交杂到一起，让读者烧脑子，增大读者阅读难度，影响读者愉快的心情。 2. 文字精简，防止作者为了介绍一个知识点而长篇大论。3.碎片化阅读时间，上班族没有大段的连续学习时间。可以借鉴SuperCell公司的游戏设计理念，3-5分钟一局。
2. 卡片内容。可以借鉴论文的格式，先给出摘要（结论/速查表），再加上大篇幅说明和论证。不需要参考文献。人类的学习方式是先“知其然”，后“知其所以然”。
3. 卡片命名。不能单纯顺序编号，否则后续添加卡片导致编号全部都要改。可以采用二级编号法。先将全部C/C++语法分成若干模块Block，然后每个模块下面若干卡片Card。落实到每个卡片的markdown文件命名，就是B<m>C<n>_xxxxx.md。B和C是固定的，是Block和Card的首字母，m和n是编号，xxxxx是卡片标题。
4. 导航。C/README_C.md和CPP/REAMD_CPP.md是导航页。每个小卡片用一句话概括，可以做成超链接跳转。本项目地址是https://github.com/yangjiacheng1996/cpp 。你需要先完成导航的撰写，然后每个卡片后面留一个空格，让我审批和打勾，只有打勾的卡片才允许你继续编写对应的卡片。防止Block切分有问题，因为我手上有大量“侯捷”的C++书籍，我可以对照目录进行审批。
5. 编写工具：我将采用/speckit 的一系列斜杠命令进行卡片撰写，子命令在项目根目录的.opencode中，绝对不允许你修改.opencode/中的文件。
